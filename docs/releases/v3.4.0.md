## Changelog

- Added compatibility with Kubernetes versions 1.33.x and 1.34.x.
- Added a new distribution named `harbor-ha`, where Redis, Postgres and storage are external. You can find out how to use it in the [examples](../../examples/harbor-ha/)

> [!WARNING]
>
> If you are upgrading from a version <= v3.2.0, read the release notes for [v3.3.0](https://github.com/sighupio/add-on-registry/releases/tag/v3.3.0).

## Upgrade path

### Pre-upgrade

- Backup the database that Harbor is using underneath.
- If you are using an external database, make sure the version of PostgreSQL is >= 12.

### Upgrade

The `Core` component of Harbor automatically runs the needed Database migrations, so normally it is sufficient to just deploy the new module version.

You can make sure that the migration runs on a single Pod by:

1. Scaling down to zero the existing `core` deployment: `kubectl scale deploy -n registry core --replicas 0`

> [!WARNING]
>
> This will cause some downtime. Warn your users about this maintenance task.
<!-- markdownlint-disable MD029 -->
2. Download new module's version, make sure that the `replicas` of the `core` deployment is set to `1`, then apply the `kustomize` project
3. When the migration is finished, you can set the desired number of replicas and apply again
